# استراتيجية الاختبار

> الغرض: خريطة الاختبار الكاملة — الوحدة والتكامل وe2e والبوابات
> والإثباتات الحية واختبار الحمل، وقواعد الأمانة في الادعاء.
> الشيفرة مصدر الحقيقة: `.github/workflows/ci.yml` و`deploy-smoke.yml`.

## 1. الطبقات (كلها في CI)

| الطبقة | ما تثبته | الأداة/الأمر |
|---|---|---|
| واجهة (وحدة) | مكونات ومنطق jsdom بلا قاعدة | `npm run test -w frontend` (vitest) |
| خلفية (وحدة) | وحدات الخلفية بلا قاعدة (`NODE_ENV=test` يملأ أسرارًا وهمية) | `npm run test -w backend` |
| تكامل قاعدة | المعاملات/الأقفال/القيود الفريدة على Postgres خدمي يُفرَّغ بين الاختبارات | `npm run test:integration` (حرس يرفض قاعدة غير محلية) |
| e2e هرمية | رحلات متصفح بلا خلفية/قاعدة/شبكة — `page.route` يحاكي `/api` بالكامل | `npm run test:e2e` (Playwright chromium على Vite :5173) |
| حزام QA العابر للمسارات (r305) | 73 مواصفة على نفس النموذج الهرمي | `npm run test:r305` |
| iOS WebKit حقيقي | عقود الويب على iPhone 13 (دفعًا فقط — أثقل متصفح) | `npx playwright test --project=webkit-iphone` |
| موبايل | render-net (كل مسار يُصعد) + contract + tokens + حزم ≤ 8MB | انظر [mobile.md](mobile.md) §4 |
| انحراف السطح | التقاط حي 72 مسارًا للبناء الإنتاجي + كاشف انحراف مقابل خط أساس ملتزم | `surface-drift` (فحص صارم) |

## 2. البوابات النوعية (وظيفة design-gates + ما بعدها)

- `tokens:check` — الأنصاف المولّدة (CSS للويب + TS للموبايل + منفذ
  العلامة RN) مطابقة بايتًا لـ`shared/design-tokens.json`.
- `check-icons` (Lucide فقط) · `logo-gate` · `check-motion-tokens` ·
  `check-colors --strict` (لا hex/rgb خام خارج التوكنات) ·
  `check-raw-css --strict` (لا font-size/radius/spacing خام) +
  `test-raw-css-gate` (31 حالة طفرية تثبت أن البوابة عمياء الصفر) ·
  `check-csp-hash` (بصمة bootstrap السمة) · `verify-parity-export`
  (زوج parity 168/168).
- `a11y-gate` — axe حقيقي serious/critical على الصفحات العامة
  (/ · /auth · /404) × فاتح/داكن × 390/1280، RTL، مسنِد نحو خط أساس
  لا يتراخى إلا للأحكم (exit 2 = عطل بنية).
- `check-bundle-size` — سقوف وزن JS للويب (إجمالي مضغوط ≤ 700KB؛
  الدخول ≤ 80KB؛ pdf ≤ 110KB).
- `zero-trace.sh` — بوابة الصفر-أثر للمحتوى/الأسماء (نصف التاريخ في
  git مقصود له حتى المستودع الجديد)؛ نصف **قاعدة البيانات** يركب فحص
  الدخان بعد النشر (§3).
- deadcode/size-gate: جرد الشيفرة الميتة وسقوف الحجم على مسارات إضافية.

## 3. الإثباتات الحية (ما بعد الدمج)

- **deploy-smoke** (عند كل نشر): انتظار `buildId == SHA` ← صحة + 12
  دخولًا بكلمة العرض + endpoint حرج لل تطبيق + مقارنة OpenAPI
  (الحي مقابل الملتزم، additive فقط) — الفشل يفتح issue تلقائيًا،
  ويتضمن **فحص قاعدة البيانات** (مسح كل عمود نصي ضد أسماء الحقب
  المتقاعدة عبر psql).
- **login-all** (`scripts/e2e/login-all.mjs`): دليل قبول المالك في
  متصفح حقيقي — كل حساب من الاثني عشر يُكتب **يدويًا حرفًا حرفًا**
  (لا زر سريع)، يتحقق من الوصول للوحة دوره، لقطة لكل دور. أي فشل
  يفتح issue.
- **android-smoke**: رحلات مايسترو الخمس على المحاكي بوصفة المالك +
  بوابة logcat لتوقيعات الانهيار — التفصيل في [mobile.md](mobile.md) §5.
- **دخان النشر المحلي**: `npm run smoke` (سكربت `scripts/smoke-deploy.mjs`).

## 4. اختبار الحمل (k6)

الأمر (الأرقام صالحة معه فقط):

```bash
K6_BASE_URL=https://ulara.vercel.app k6 run scripts/load/k6.js
```

- **السيناريو**: صعود 0→20→60→100 VU خلال ~4.5 دقيقة؛ كل VU يمشي
  دخولًا ← `/auth/me` ← قائمة مقررات ← سؤال ذكاء ← سبات إيقاعي (شكل
  الفصل الحقيقي). الدخول مرة واحدة في `setup()` لكل حساب (داخل سقف
  المصادقة 10/15د/IP بالبناء).
- **عتبات القبول** (مثبتة في السكربت): `http_req_duration{kind:api}`
  p95 ‏< 800ms · نسبة checks ‏> 0.99 · `http_req_failed` ‏< 0.01 —
  **429 الصادق من المحدِّد يُحتسب نجاحًا** (الرد يحمي التطبيق لا
  يخونه).
- **دروس الجولات المسجلة** (لا تعيدها): (1) دخول كل تكرار ~1300
  دخول من IP واحد قاس المحدِّدَ لا التطبيق، و`/api/v1/me` القديم
  404 — صُحح السكربت: الدخول إلى `setup()` والمسار `/auth/me`.
  (2) ميزانيات صغيرة: `K6_MAX_VUS`/`K6_MAX_SECONDS`/`K6_ACCOUNTS`
  تشغّل أشكالًا محدودة على صناديق صغيرة بلا لمس شكل 100-VU —
  جولة 10VU/20ث داخل ميزانية 1000 طلب/15د/IP سجلت p95 ‏13.5ms و0%
  فشل. (3) على الإنتاج: توقع اشتباك المحدِّد العام بعد ~1000 طلب
  من IP المشغّل؛ الذيل 429 هو التطبيق يحمي نفسه.
- الحسابات المعتمدة: جدول `@test.ly` فقط (لا تختلق حسابات).

## 5. قواعد الأمانة

1. **لا ادعاء بلا تشغيل**: كل نتيجة تُوسم بمصدرها (تشغيل حي/سجل/جهاز
   المالك عبر EAS). «متحقق منه في الصندوق» ليس «متحقق منه على جهاز».
2. الجرائد تُملأ لا تُخفى: أي تراجع في عتبة أو ميزانية يُسجَّل في
   `docs/ops/LEDGER.md` مع الدليل.
3. الأعطال تُشخَّص من الأثر (سجلات/لقطات/logcat) لا من الظن — الدرس
   الأصلي: أداة غير مثبتة أصلًا لا يمكن أن تفشل في رحلتها.
4. الفشل يعمل: أي فشل بوابة يرفع أدلة (artifact) للتحقيق الجنائي.
