### E.2 — دخان النشر #43–#46: **تعارض بنيوي، مشخَّص ومُثبت محليًا، والرقعة بيد المالك**

**الفشل الحالي** (منذ `15b50d2`، القضية #46): خطوة «login-all» تفشل
12/12 بـ `locator.click: Timeout 120000ms` — بينما «Login ×12» على
مستوى API **تنجح كلها** في الخطوة السابقة.

**الجذر** (مُعاد إنتاجه محليًا حرفيًا): البيئة المعزولة تُقلع **بلا
`NODE_ENV=production`** عمدًا — لأن سياسة حسابات الاختبار r352 §5 تصنف
العدّاء بلا VERCEL على NODE_ENV≠production بأنه غير إنتاجي فيسمح
بالفيكسشرات كاملة (ومنها OWNER). لكن تقديم SPA في Express مربوط
بالسطر `serveStatic: isProd` في env.ts — فلا يُخدَم أي ملف ثابت، و
`GET /auth` يرد `Cannot GET /auth` (مُثبت محليًا)، فيقف المتصفح على
صفحة خطأ فارغة وتنفد النقرات. **r355 عالج السبب الآخر (شكل البذرة)
وصحّح، لكن هذا الوجه لم يكن ظاهرًا إلا للمشي المتصفحي في CI.**

**الإثبات المحلي** (نفس شجرة main): الإقلاع بوضع «preview-like» —

```bash
NODE_ENV=production VERCEL=1 VERCEL_ENV=preview ULARA_TEST_ACCOUNTS=1 \
DATABASE_URL=… PORT=4100 node backend/dist/index.js
```

— يعطي في سجل الإقلاع: `Test accounts ensured (12 jobs)` **و** `Serving
frontend`، و`/auth` يرد وثيقة SPA العربية، **وlogin-all يخضرّ 2/2**
(student عبر المختار كاملًا + student2 مباشرة، ~2.4 ث/حساب).

**الرقعة المقترحة على المالك** (ملكية CI — لم تُمسّ): في
`.github/workflows/deploy-smoke.yml`، خطوة «Boot the app»، أضف إلى
كتلة env الثلاثة:

```yaml
          NODE_ENV: production
          VERCEL: "1"
          VERCEL_ENV: preview
```

هذا هو الدلالي الصحيح لا حيلة: إنه **بالضبط** شكل نشر معاينة Vercel
(بناء إنتاجي يخدم الثابت + زمن تشغيل غير إنتاجي تسمح فيه §5
بالفيكسشرات) — نفس ما يجري على ulara.vercel.app في نشرات المعاينة.
(بديل أدنى غزوًا لو فضّل المالك: فك ارتباط `serveStatic` عن isProd
بعلم صريح في backend/src/env.ts — لكنه لمس الخلفية.)
