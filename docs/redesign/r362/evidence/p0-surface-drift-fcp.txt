## Verdict + fix
Not a code regression: 72/72 cells pass locally, the failing cell paints at 28-76ms,
and the cell that failed is the one whose ratio limit is smallest in absolute terms.
A ratio-only budget on a sub-100ms baseline decides the verdict by runner warm-up
(cold browser process + V8 compile of the entry chunks), not by a regression.

Measurement fixed at the cause (drift.ts + inventory-types.ts): the effective limit
is max(baseline x ratio, fcpMinLimitMs=600). The ratio still gates every route;
the floor only ever binds for shell-paint routes, so a real blocking-JS regression
(hundreds of ms on every cell) still trips it.
