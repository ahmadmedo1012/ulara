# دليل تشغيل الطوارئ

> الغرض: إجراءات المالك/المشغّل عند الأعطال — فشل النشر، استيقاظ
> القاعدة، تدوير الأسرار، إنقاذ الدخول، وعمليات القاعدة (db-ops).
> كل أمر هنا موجود في الشجرة؛ الشيفرة مصدر الحقيقة.

## 1. فشل النشر

1. **حدّد**: `curl -s https://ulara.vercel.app/api/v1/health` — إن كان
   `buildId` لا يطابق رأس `main` فالنشر لم يكتمل بعد (deploy-smoke
   يستقصي حتى 20 دقيقة ويفتح issue عند الفشل).
2. **شخّص من الأثر**: اقرأ issue الفحص وartifact الأدلة (لقطات
   login-all، logcat المحاكي في android-smoke، توقيعات الانهيار).
3. **راجع**: من لوحة Vercel (Deployments) آخر نشر صحيح، أو ادفع
   إصلاحًا — الأتمتة تعيد النشر والتحقق من الدخان ذاتيًا.
4. **تراجع OTA إن كان التغيير جوالًا**:
   `npx eas-cli update:republish --branch production <update-id-الجيد>`
   أو `update:rollback --branch production` (المستخدمون يرون السابق
   عند الإقلاع القادم).

## 2. القاعدة (Neon) — الاستيقاظ والترحيلات

- **Cold start**: Neon المجانية تصفر الحساب بعد الخمول؛ أول طلب يدفع
  استيقاظًا دون ثانية — سكربت `backend/scripts/migrate-deploy.mjs` يعيد
  المحاولة حتى الاستيقاظ. لا شيء يلزم إبقاؤه دافئًا على جانب الويب
  (الخدمة دائم الاستيقاظ على Vercel).
- **فشل ترحيل**: شغّل يدويًا `npm run db:deploy` مع `DATABASE_URL`
  للإنتاج وراقب خرج prisma؛ القاعدة الحية تدير الترحيلات في خطوة
  البناء (نفس المسار الذي يستخدمه الإنتاج).
- **دخول «الخادم يستيقظ»**: واجهة الدخول تعيد المحاولة صامتًا ×2
  برسالة صادقة — لا صفحة ميتة.

## 3. تدوير الأسرار

| السر | الإجراء | الأثر |
|---|---|---|
| أسرار JWT (≥32) | متغيرات Vercel ← إعادة نشر | كل الجلسات تسقط — المستخدمون يعيدون الدخول |
| `INTERNAL_SERVICE_TOKEN` = `CRON_SECRET` | متغير واحد يحدَّث في المكانين معًا (سر واحد بنقلتين) | cron والمشغّل يستأنفان فورًا |
| كلمة حساب عرض | `npm run db:rotate-password -- --email <الحساب> --new-password-env NEW_PASSWORD --yes` | **الشفاء ذاتي البنيوية** يعيدها لكلمة العرض خلال يوم (§4) — دوّنها قبل أي عرض |
| GitHub PAT / `EXPO_TOKEN` | إن لامسها أحد: أعد إنشاءها من مزودها ثم حدّث سر Actions | لا تغيير في الشجرة |
| مفتاح توقيع أندرويد | لا يُدوَّر — يُنسخ احتياطيًا خارج الجهاز مرة؛ فقدانه = هوية قناة جديدة (إزالة تثبيت واحدة للمنتقلين) | قناة المتجر منفصلة |

- رفع الحد الأدنى للإصدار (حاجب «يلزم تحديث التطبيق»):
  متغيرات Vercel ← `MIN_APP_VERSION=1.1.0` (+`APP_DOWNLOAD_URL`).

## 4. إنقاذ الدخول (ensure-test-accounts)

**الحادثة الأصلية (الدرس)**: حسابان كانا خارج جدول الحسابات فبقيت
كلمتاهما مدوّرتين — «الدخول لا يعمل». العلاج البنيوي:

- الجدول الوحيد الآن 12 حسابًا (`@test.ly`/`12345678` —
  `backend/src/modules/auth/test-accounts.data.ts`)، ومع
  `ULARA_TEST_ACCOUNTS=1` (مفعّل على الإنتاج) تعيد تمريرة ensure كل
  حساب إلى كلمة العرض: عند الإقلاع، وفي cron اليومي، وعند الطلب
  `POST /api/v1/jobs/test-accounts` (سرّ الخدمة). اليدوي:
  `npm run db:ensure-test-accounts`.
- **قبل عرض حقيقي**: دوّر كلمات العرض بالمسار في §3، ولا تعِد بذر
  الإنتاج أبدًا لتغيير كلمة.
- إثبات CI إلزامي: login-all يكتب كل حساب يدويًا في متصفح حقيقي
  ويتحقق من لوحة الدور (انظر [testing.md](testing.md) §3).

## 5. عمليات القاعدة (db-ops)

```bash
npm run db:backup     # إلى backups/ مع sha256
npm run db:restore -- --url-env <TARGET> --file backups/<ملف>   # قاعدة عزل فقط
npm run db:verify      # جداول/ترحيلات/عدّ صفوف مقابل مرجع
```

- الاستعادة إلى قاعدة حيّة مرفوضة افتراضيًا؛
  `--confirm-live-restore` هو التجاوز الواعي للطوارئ فقط.
- **انقل النسخ خارج الخادم** — نسخة على صندوق القاعدة ليست نسخة؛
  هذه الخطوة الوحيدة المتبقية على المالك منذ البداية.
- كل جولة تمرين تُسجَّل في `docs/ops/LEDGER.md` مع الأدلة؛ آخر جولة
  كاملة: نسخ ← استعادة في عزل ← `db:verify` PASS ← خلفية ثانية على
  القاعدة المستعادة ← إسقاط القاعدة.
