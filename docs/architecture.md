# معمارية أُلارا

> الغرض: القرار المعماري الحي — البنية، قواعد المنتج، التعدّد المؤسسي،
> خريطة الوحدات الست، وعقد الـAPI. ما نُفّذ وحُكم عليه يُختصر؛ وما أُلغي
> يُذكر قرارًا ملغى بلا تفاصيل. المصدر التفصيلي للسلوك: الشيفرة نفسها.

## 1. البنية العامة

مستودع واحد (`ulara`)، فرع واحد (`main`)، نشر تلقائي:

- **backend** (Node/Express + Prisma + PostgreSQL): وحدات نطاق في
  `backend/src/modules/**` ومسارات HTTP في `backend/src/http/routes/**`
  (33 ملف مسارات). مصادقة argon2id + JWT HS256 مع كوكي تحديث
  `ulara_refresh` (HttpOnly) — انظر §6.
- **frontend** (React + Vite + TanStack): صفحات في `frontend/src/pages/**`
  لكل دور، قشرة موحّدة `AppShell`، بحث عام، وضعا فاتح/داكن.
- **apps/mobile** (Expo SDK 58 / RN 0.88): expo-router بهيكل أدوار مطابق —
  التفصيل في [mobile.md](mobile.md).
- **shared/**: `design-tokens.json` (مصدر التوكنات الوحيد) وجدول حسابات
  الاختبار (المصدر: `backend/src/modules/auth/test-accounts.data.ts`).
- **النشر**: Vercel (ويب + API عبر `api/index.ts`) + Neon PostgreSQL.
  التفصيل في [deployment.md](deployment.md).

## 2. قواعد المنتج غير القابلة للتفاوض

1. منتج **أُلارا** واحد: علامة واحدة، شيفرة واحدة، نظام تصميم واحد
   (`DESIGN.md` + التوكنات). لا شعار/ألوان/سمة لكل جامعة، لا white-label،
   لا نطاقات فرعية.
2. المؤسسات معزولة البيانات أكاديميًا وعضويًا وصلاحيّيًا وإداريًا.
3. اسم الجامعة وحقائقها **سياق تنظيمي معروض** — ليس هوية بصرية ولا ادعاء
   اعتماد رسمي: أُلارا منصّة مستقلّة، وبيانات مؤسّسة العرض معلَنة كبيانات
   عرض (بلا أي تبنٍّ رسمي — تصحيح موثّق في موجة الهوية).
4. هوية المستخدم عالمية (بريد فريد)؛ **الدور يعيش في العضوية** لا في
   المستخدم؛ OWNER كيان عالمي مغاير لمسجل عام المؤسّسة (ADMIN).
5. سياق المؤسّسة يُحلّ **على الخادم** من العضوية في كل طلب — لا ثقة بأي
   معرّف مؤسّسة يرسله العميل.

## 3. التعدّد المؤسسي (منفّذ بالكامل)

**القرار المعتمد (البديل أ):** قاعدة PostgreSQL واحدة + ملكية مؤسسية
صراحة (`Institution`/`Membership` بـ`@@unique([userId, institutionId])`)
+ تفويض على مستوى التطبيق. نُفّذ منذ r178 وطُبّق على الإنتاج، وخطة
الترحيل M1–M5 أُنجزت كاملة (backfill ثم قيود مركّبة `(institutionId, …)`
للكليات/المقررات/رقم القيد/حقائق الجامعة/القدرات).

- **حلّ السياق**: `lib/profile-scoping.ts` يحقن `institutionId` المتحقق؛
  النمط `buildScopedUserWhere` يعمَّم على كل استعلام مؤسسي.
- **نطاق البيانات**: المحتوى الأكاديمي والملفات مؤسسية؛ الكتالوجات المُدارة
  (كتب/MOOC/وظائف/تدريب/إنجازات) مشتركة منصّة؛ الرسائل داخل مؤسّسة واحدة؛
  `AuditLog` سجل واحد بعمود `institutionId?` (NULL = نطاق منصّة).
- **الأمانة المؤسسية**: تسجيل الدخول برقم قيد مكرَّر بين مؤسستين يرد
  `400 REG_NUMBER_AMBIGUOUS` مع اختيار المؤسّسة (`institutionSlug`).

## 4. قرارات معمارية حيّة

| القرار | الحالة |
|---|---|
| **تأجيل RLS في PostgreSQL** | مؤجَّل بقرار موثّق (Prisma لا يضمن `SET app.institution_id` على اتصال الطلب — قضايا #5128/#12420). إعادة الفتح عند: دعم Prisma الأول، اشتراط امتثال مؤسسي، أو قرار منتج — وحينها: دور اتصال مخصّص + سياسات على `Grade`/`WatchEvent`/`BinaryObject` أولًا. العزل الحالي متحقَّق من الطرف للطرف (اختبارات عابرة للمؤسستين + فحص دخان حي). |
| **الجدولة** | مجدول داخل العملية (إقلاع + كل 24 ساعة): مزامنة حقائق مؤسّسة العرض + تقليم `LoginEvent` (احتفاظ 180 يومًا). على Serverless: cron المنصة يضرب `GET /api/v1/jobs/daily` بسرّ `CRON_SECRET`. حرس تعارض 409 مع الزناد اليدوي. |
| **التخزين** | `STORAGE_DRIVER` ∈ local/postgres/s3؛ `s3` يفشل مغلقًا بدون متغيراته. رفع الفيديو عبر توقيع مسبق مباشر إلى S3 (لا يمرّ بايت عبر دالة). |
| **حدود PDF صادقة مع المضيف** | سقف 4 MiB على Vercel (جدار 4.5 MB للمنصة) و20 Miب عند الاستضافة الذاتية؛ القيمة الفعلية تُعلَن في `GET /api/v1/status` وتفرضها الأسطح الثلاثة؛ GET لملف أكبر من سقف المضيف يرد 413 عربيًا (مع RANGE يقطّع تحت الجدار). |
| **عقد الـAPI additive-only** | الحقول لا تُحذف/تُ rename؛ الجديد يضاف في أي مستوى. يفرضه `backend/tests/contract/api-contract.test.ts` + مقارنة المولَّد الحي بالمُلتزَم (additive) في فحص الدخان. |
| **حدود المعدل** | عام 1000/15د/IP؛ أسطح المصادقة والذكاء 10/15د/IP (الفشل فقط للمصادقة). العميل يقرأ `error.code` ولا يفرّع على نص عربي. |

## 6. عقد الـAPI والمصادقة

- **OpenAPI 3.1** مولّد من الشيفرة: `npm run api:openapi` ←
  [api/openapi.json](api/openapi.json) (255 عملية في 218 مسارًا). أبواب الأدوار/القدرات
  غير ممثَّلة لكل عملية — المصدر: `requireRole`/`requireCapability` في
  ملفات المسارات نفسها.
- **نموذج التوكن**: وصول JWT 15 دقيقة (Bearer)، تحديث JWT 7 أيام في كوكي
  `ulara_refresh` (HttpOnly, SameSite=Strict) **حصرًا** — لا حقل جسم ولا
  معامل استعلام. عميل جوال: التقط `Set-Cookie` بعد login/refresh وخزّنه
  (SecureStore) وأعده `Cookie: ulara_refresh=…` عند `/auth/refresh`.
  الفشل 5 مرات يقفل 15 دقيقة (429)؛ المساواة الزمنية على كل رفض.
- **الذكاء الاصطناعي**: `aiMode` في `/status` (محلي أو مزوّد خارجي عبر
  OpenRouter مع تدهور أمين عند نفاد الحصة)؛ بث SSE بـfetch+reader (لا
  EventSource)؛ كل رد يُسند لمصدره.

## 7. قرارات ملغاة/متجاوزة (بلا تفاصيل)

- **قرار الاستضافة r182** (البقاء على المضيف السابق مع مقارنة البدائل):
  ملغى — الإنتاج انتقل إلى Vercel + Neon؛ السجل التاريخي حُذف مع موجته.
- **خطة الترحيل M0–M5 للتعدّد المؤسسي**: منفّذة بالكامل — بقيتها
  التاريخية حُذفت؛ الحالة الحية في §3.
- **أمواج إعادة التصميم البصري المرجعية (r188–r191)**: متجاوزة — النظام
  الحي هو قانون `DESIGN.md` (انظر [design-system.md](design-system.md)).
- **جرد نطاق البيانات المرحلي (77 نموذجًا بفئاته الست)**: أُنجز غرضه
  (الترحيل أعلاه)؛ المخطط الحي: `backend/prisma/schema.prisma` (89
  نموذجًا، ترحيل أساس واحد `0001_ulara_baseline`).

## 8. الأمانة والحدود (قلها إن سُئلت)

- الذكاء الاصطناعي: وضع محلي صادق بلا مزوّد خارجي مفعّل، والتدهور معلَن.
- نسب الاستلال/المحتوى الآلي: **مؤشرات محاكاة** — ليست أدلة أكاديمية.
- مؤسسة واحدة مرجعية (بيانات عرض) + مؤسسة عزل للتجربة — لا ادعاء جاهزية
  إنتاج واسع؛ النطاق: عرض جامعي وطيار 5–10 طلبة.
- كل رقم تقديري في الواجهات يحمل لاحقة/علم «estimated» — اتبع النمط.
