# نظام التصميم (ds)

> الغرض: البوابة المختصرة إلى نظام التصميم الحي — التوليد، القواعد
> الجوهرية، أوراق ds-*، والبوابات. **القانون الكامل المنشور في الشيفرة
> هو `DESIGN.md` في الجذر** — هذا الملف لا يكرره بل يدلك عليه وعلى
> البوابات التي تفرضه.

## 1. النظام في سطرين

ورقة رسم معماري: أرضيات ورقية محايدة دافئة، حبر غرافيتي، خطوط شعرية
ومصفوفات مسطّرة، زوايا شبه مربعة، صوت رسم تقني بأرقام monospace مقوّسة
(`[01]` وبيانات وصفية)، فراغ سلبي سخيّ مضبوط، و**إشارة برتقالية واحدة**
> تُنفق بانضباط على التفاعل النشط والتعليق المفتاحي وزر الدعوة الأساسي.
الوضع الداكن هو الفحمي نفسه أرضًا — نظام مكمّل لا انعكاس.

## 2. التوليد والانحراف (خط الدم)

- المصدر الوحيد: `shared/design-tokens.json` ←
  `npm run tokens:build` يولّد: نصوص الويب (`frontend/src/styles/tokens/
  tokens.generated.css`) + نوع الموبايل (`apps/mobile/src/design/
  tokens.generated.ts`) + منفذ العلامة RN.
- بوابة الانحراف `npm run tokens:check` (CI): المولَّد الملتزم يجب أن
  يطابق بايتًا. **لا تحرّر مخرجًا مولَّدًا يدويًا أبدًا** — عدّل
  المصدر ثم أعد التوليد.
- زوج parity (`unified-parity.css` + `shared-design-system.css`) غير
  مستورد في التطبيق عمدًا — سطح تحقق داخلي تفرضه بوابة 168/168.

## 3. القواعد الجوهرية (المخالف = فشل CI)

1. **الألوان عبر التوكنات فقط**: لا hex/rgb خام خارج `tokens`
   (`check-colors --strict`)؛ نغمات الحالة عائلات محسوبة
   (`--c-{mint,yellow,rose,sky,…}-{bg,ink,deep}`) بتباين deep-vs-bg
   ≥4.5 في الوضعين. الذهبية **للإنجاز/الحالة حصرًا** — ليست لونًا
   ثانيًا للإشارة أبدًا.
2. **الطباعة**: ثلاثية OFL مستضافة ذاتيًا — Alexandria للعرض،
   IBM Plex Sans Arabic للمتن، IBM Plex Mono للصوت التقني
   (`[NN]`، أرقام tabular، `dir=ltr` للأسرار اللاتينية). أرضية
   عربية 13px؛ **صفر letter-spacing على العربية**؛ التراتب بالوزن
   والسلّم لا بـUPPERCASE.
3. **الحركة بالقياس**: سلّم `--t-*` على منحنى ds واحد؛ كشف بمستوى
   الكتل (الانقسام بالكلمات فقط — الانقسام بالأسطر يكسر تشكيل
   العربية)؛ `prefers-reduced-motion` يصفّر كل مدة ويقف المحتوى
   كاملًا ساكنًا؛ لا scrolljacking؛ صفر إعادة عرض React لكل نبضة
   (كروم التمرير يكتب CSS vars على rAF).
4. **الرسم الأول فقط**: أيقونات Lucide (`check-icons`)، خطوط SVG
   أصلية؛ لا 3D، لا ملصقات، لا اتجاه فني منافس.
5. **RTL ومنطقية الاتجاه**: خصائص منطقية (inset-inline…) دائمًا؛
   لا خصائص فيزيائية يسار/يمين؛ الأرقام غربية (`ar-LY latn`).
6. **الوصول**: تباين AA لكل نص (الإشارة للنص عبر `--accent-ink`
   5.16 AA)؛ حلقة تركيز واحدة ≥3:1؛ الجداول/الرسوم لها بديل نصي.
7. **الملف الخام**: لا font-size/border-radius/spacing خارج التوكنات
   (`check-raw-css --strict`)؛ بصمة سكربت السمة في CSP (`check-csp-hash`).

## 4. الأوراق (الاستهلاك)

- التطبيق: `frontend/src/styles/` — أوراق الدور بأسماء ds-*:
  الطالب `styles/student/ds-{core,courses,dashboard,schedule,supplemental}.css`،
  الأستاذ `styles/teacher/ds-core.css`، والمشترك الإداري/البحثي
  `styles/shared/ds-admin-owner.css` و`styles/shared/ds-research.css`.
- الهبوط: `styles/landing/**` (لوحة أُلارا — القانون في `DESIGN.md` §5).
- الموبايل: طبقة سيمانتك فوق التوكنات المولدة — القواعد في
  [mobile.md](mobile.md) §3 و`DESIGN.md` (R325 قواعد التطبيق).

## 5. قواعد تطوير النظام

1. القانون هو `DESIGN.md`؛ أي تعديل يعبر بواباته (لا استثناءات
   موثقة جديدة — الحذف لا الإخفاء).
2. قيمة جديدة تدخل عبر `shared/design-tokens.json` ثم توليد — لا
   قيمة يدوية في ورقة.
3. أضف مقعدًا دلاليًا (مثل نغمات حالة) لا لونًا خامًا؛ الإشارة
   البرتقالية تبقى واحدة لكل سطح.
4. التاريخ: أمواج إعادة التصميم السابقة **ملغاة** بلا تفاصيل (هي
   ليست تعليمات أبدًا) — الجدول الحي في `DESIGN.md` §«Gates & history».
